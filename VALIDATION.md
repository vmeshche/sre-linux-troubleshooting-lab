# Проверка сценариев

Проверено **9 октября 2026 года** на ARM64:

| Компонент | Окружение |
|---|---|
| Userspace | Ubuntu 26.04.1 LTS (образ ubuntu:26.04) |
| PID 1 | systemd 259.5-0ubuntu3.4 |
| Ядро | 6.12.76-linuxkit, Docker Desktop на macOS |
| Контейнер | Отдельный, privileged; собственные PID и cgroup namespace |
| strace | 6.19 |
| lsof | 4.99.4 |
| perf | 7.0.14; пакет linux-perf 7.0.0-38.38 |

## Пройденные проверки

- Сборка четырёх C-примеров с `-Wall -Wextra`, установка и проверка unit-файлов через `systemd-analyze verify`.
- Подготовка стенда и проверка окружения, в том числе из обычной учётной записи через sudo.
- Конфигурация: неуспешный старт, ENOENT с реальным путём, успешное исправление, EACCES под `lk7-demo`, повторный успех.
- Порт: old application, ошибка Address already in use, совпадение PID слушателя с unit, смена на new application.
- FIFO: подключение strace к ожидающему процессу, доставка строки, наблюдение read/write, отключение трассировщика при живой службе.
- Лог: файл 16 MiB, удаление имени, `NLINK=0` и размер через FD, переоткрытие по SIGUSR1, исчезновение удалённого объекта из lsof.
- CPU: работающий вычислительный процесс, ограниченная трассировка, perf stat, perf record, обнаружение `mix_numbers` в report.
- Повторный сброс без ошибки и успешная проверка исходного состояния.

## Границы проверки

Это проверка сценариев Linux с настоящим systemd, **не проверка установки VirtualBox**. Драйверы, ARM64/AMD64-гипервизор, SSH и аппаратные события perf на конкретных ноутбуках здесь не проверялись. Примеры используют переносимый C и собираются локально, однако отдельный прогон на AMD64 не выполнялся.

Контейнер использовал ядро LinuxKit, а не штатное ядро Ubuntu VM. Поэтому имена WCHAN, доступные события perf, часть служебного вывода и точные времена могут отличаться. Сценарий CPU содержит запасной разбор реального сохранённого профиля.

Неблокирующие сообщения нашего perf: `Failed to open /proc/schedstat` при записи и отсутствие `tips.txt` при просмотре. Запись при этом завершилась: 488 выборок, потерянных выборок 0, символ `mix_numbers` найден. Сохранённый вывод не скрывает эти особенности.

## Новый опыт ELF и линковки: 15 октября 2026 года

Все восемь bash-блоков опыта 0 и расширения про линковку выполнены по README в отдельном контейнере **Ubuntu 26.04.1 ARM64**, ядро **6.12.76-linuxkit**. Инструменты: **GCC 15.2.0**, **GNU Binutils 2.46**, **strace 6.19**. Для ptrace контейнеру разрешён SYS_PTRACE и отключён его seccomp-фильтр; в инструкции студентам эти настройки не требуются, там используется Ubuntu VM.

Проверены фактические результаты:

- Объектные файлы ELF; в main.o символы `T main`, `U calculate`, `U printf`, `D initialized`, `B zero_initialized`, `R greeting`; в calculate.o — `T calculate`.
- Секция `.bss` имеет тип `NOBITS`.
- После линковки функция `calculate` доступна в `nm` и дизассемблере; `objdump -S` показывает строку `return value * 6;`.
- Обычный бинарник и его stripped-копия печатают `hello from ELF: 42`. В обоих trace `write` отправляет 19 байт.
- После `strip --strip-all` обычный `nm` сообщает no symbols, `nm -D` по-прежнему показывает динамический printf.
- Сборки с `.a` и `.so` дают одинаковый результат. `demo-archive` не зависит от libcalculate.so, но зависит от libc.so.6. В `demo-shared` есть NEEDED на libcalculate.so и RUNPATH `$ORIGIN/lib`.
- Изолированная копия `demo-shared` без библиотеки завершается с кодом 127. В trace есть поиск libcalculate.so с ENOENT. Путь через LD_LIBRARY_PATH для одного запуска восстанавливает результат.
- Команды повторно выполнены в том же каталоге, затем весь новый сценарий пройден обычным пользователем UID 1000 без sudo: повторная сборка, strace и strip копии работают.

Сервисные инциденты и perf в этой проверке заново не прогонялись: их программы и unit-файлы не менялись, прежняя проверка описана выше. У `check-environment.sh` дополнен список требуемых инструментов и обновлён текст готовности; синтаксис проверен `bash -n`. Полный запуск этой проверки требует VM с systemd PID 1. Отдельный прогон нового опыта на AMD64 и в VirtualBox не выполнялся; листинги и адреса там будут отличаться.
